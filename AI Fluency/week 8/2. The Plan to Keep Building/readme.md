# The Plan to Keep Building: Next Case Study Strategy

## 1. How to Add the Next Case Study

To keep `artiwary.netlify.app` consistent and easy to maintain, every future case study will follow the same three-beat structure:

### The Problem

Define the exact user friction, technical bottleneck, or domain challenge in approximately two sentences. The goal is to make the reason for building the project immediately understandable.

### What I Did

Explain the solution, including the system architecture, technology stack, important engineering decisions, and any AI/ML pipeline used.

### What Came of It

Document concrete outcomes wherever possible, such as model accuracy, latency improvements, test results, deployment performance, uptime, user feedback, or other measurable results.

### Execution

Once the case study is written, I will add the new project card to the portfolio's existing project data structure in `portfolioData.js`. I will match the existing Apple glassmorphism design system and component patterns rather than creating a separate visual style.

After testing the project locally, I will push the changes to GitHub and verify the automated Netlify deployment, responsive layout, project links, and AI-agent information.

**Workflow:**

> **Problem → What I Did → What Came of It → Add → Test → Deploy**
